# Gadgetbridge setup for wristpull

Everything needed to set up Gadgetbridge on the phone from scratch so that `wristpull pull phone`
can fetch the data. Verified 2026-10-31 with Gadgetbridge 0.95.1 on a Mudita Kompakt
(KompaktOS / LineageOS 23.2, Android 16), a Garmin fenix 6X Pro and an
Amazfit Helio Strap.

## 1. Install Gadgetbridge

Gadgetbridge is **not** on Google Play. Official channels:

| Channel | What you get | How |
|---|---|---|
| Obtainium | stable releases | add `https://codeberg.org/Freeyourgadget/Gadgetbridge` as a source (Codeberg releases) |
| Neo Store + nightly repo | nightly builds, updated daily | add the repo `https://freeyourgadget.codeberg.page/fdroid/repo?fingerprint=CD381ECCC465AB324E21BCC335895615E07E70EE11E9FD1DF3C020C5194F00B2` |
| F-Droid / IzzyOnDroid | stable releases | search for `nodomain.freeyourgadget.gadgetbridge` |
| Manual | one APK | download from the Codeberg releases page, install with `kompakt install file.apk` (see `~/dev/mudita`) |

The stable release is sufficient: Helio Strap support arrived in 0.87.0, the last strap-specific
changes are in 0.89.0 and 0.90.0. Neo Store itself comes from GitHub
(`https://github.com/NeoApplications/Neo-Store`, one APK per release, e.g.
`Neo_Store_1.3.3_release.apk`; `kompakt get neostore` installs it over ADB).

## 2. Pair the Garmin fenix

Garmin watches need no authentication key. In Gadgetbridge: **+** → device discovery → select the
fenix → pair. Confirm the Bluetooth pairing request on the watch. Gadgetbridge then fetches the
watch's FIT files over Bluetooth and stores them on the phone under

```
/sdcard/Android/data/nodomain.freeyourgadget.gadgetbridge/files/<MAC of the watch>/
    MONITOR/<year>/MONITOR_<date>_<time>_<n>.fit      daily wellness (same format as GARMIN/Monitor on the watch)
    SEGMENT_LIST/<year>/...                             not relevant
    (ACTIVITY/, SLEEP/, ... appear once the watch has produced such files)
```

The folder name is the watch's Bluetooth MAC. These files are what wristpull imports as
source `gadgetbridge_garmin`; the parser is the same as for USB.

The watch can be connected to the phone and the computer alternately; Gadgetbridge syncs whatever
the watch still holds. Keep Garmin Connect uninstalled or disconnected, otherwise the two apps fight
over the Bluetooth connection.

## 3. Pair the Amazfit Helio Strap (authentication key required)

Zepp OS devices only talk to a phone that presents the device's authentication key, and that key is
generated by Zepp's servers during the first pairing with the vendor app. There is no way to create
it locally. This is a one-time cloud contact.

### 3.1 Pair once with the Zepp app

1. Install the Zepp app (package `com.huami.watch.hmwatchmanager`) on any phone, create a Zepp
   account with **e-mail and password** (not Google/Apple sign-in, the token tools need a password
   login), pair the strap and let it sync once.
2. **Do not unpair the strap in the Zepp app**, that invalidates the key. Leaving the strap paired
   in the Zepp account is fine, the app does not need to stay installed.

### 3.2 Retrieve the key with huami-token

`https://codeberg.org/argrento/huami-token` logs into the Zepp account and prints the keys of all
linked devices. The access/refresh token lines are only the login; the device key needs `--bt_keys`:

```sh
git clone https://codeberg.org/argrento/huami-token ~/dev/huami-token
cd ~/dev/huami-token
uv run huami-token --method amazfit --email you@example.com --password 'secret' --bt_keys
```

Output:

```
Logged in! User id: 1234567890
Getting linked devices...
Device 0:
  MAC: AB:CD:EF:12:34:56, Active: Yes
  Key: 0xa3c10e34e5c14637eea6b9efc06106
```

`Key` is the value for Gadgetbridge (already with the `0x` prefix), `MAC` identifies the strap in
the device discovery. Avoid leaving the password in the shell history (fish ignores commands that
start with a space).

Alternative from the Gadgetbridge documentation: sign in at `https://watchface.zepp.com/`, open the
browser console and run the JavaScript snippet from
`https://gadgetbridge.org/basics/pairing/huami-xiaomi-server/`; the key is the `auth_key` inside
`additionalInfo` of the returned device list. The snippet queries the US server
(`api-mifit-us3.zepp.com`); accounts in other regions may need another host.

### 3.3 Enter the key in Gadgetbridge

1. Revoke the Zepp app's Bluetooth and location permissions (or uninstall it) so it cannot grab the
   strap.
2. Gadgetbridge → **+** → device discovery → long-press the strap → **Auth key** → paste the key
   including `0x`. Alternatively after adding: device settings → Authentication → Auth key.
3. Connect. The strap's heart-rate monitoring is always on by design; workout detection sensitivity
   is configurable in the device settings.

## 4. Gadgetbridge settings needed by wristpull

Zepp OS data (heart rate, sleep, HRV, SpO2, stress, steps, workouts) is only stored in
Gadgetbridge's SQLite database, which lives in private app storage. wristpull reads the **exported**
copy, so the export must be configured:

1. **Settings → Auto export → Database export**: enable, choose the export location with the
   Android folder picker: create and select the folder `Gadgetbridge` on the internal storage
   (`/sdcard/Gadgetbridge`), interval e.g. 24 h. The exported file is `Gadgetbridge.db`.
2. **Settings → Intent API**: enable *Allow database export trigger* and *Allow activity sync
   trigger*. With these, wristpull can trigger a sync and an export over ADB without touching the
   phone. (The Zip export trigger is optional; it produces a full backup.)
3. Optional: **Auto export → GPX/FIT export** for workouts of non-Garmin devices.

Matching preference keys in the Gadgetbridge source, for reference: `auto_export_enabled`,
`auto_export_location`, `auto_export_interval`, `intent_api_allow_trigger_export`,
`intent_api_allow_activity_sync`.

## 5. Driving Gadgetbridge over ADB

```sh
adb devices                                                     # phone must show as "device"
adb -s <serial> shell pm list packages | grep gadgetbridge  # installed?
adb -s <serial> shell dumpsys package nodomain.freeyourgadget.gadgetbridge | grep versionName

# trigger a sync with all connected devices, then a database export (needs the Intent API toggles)
adb -s <serial> shell am broadcast -a nodomain.freeyourgadget.gadgetbridge.command.ACTIVITY_SYNC
adb -s <serial> shell am broadcast -a nodomain.freeyourgadget.gadgetbridge.command.TRIGGER_DATABASE_EXPORT

# what is there?
adb -s <serial> shell ls -la /sdcard/Gadgetbridge/
adb -s <serial> shell find /sdcard/Android/data/nodomain.freeyourgadget.gadgetbridge/files -type f

# the normal way: trigger sync + export, wait, pull database and new FIT files, import
uv run wristpull pull phone

# fetch manually (what wristpull pull phone does under the hood)
adb -s <serial> pull /sdcard/Gadgetbridge/Gadgetbridge.db /path/outside/the/repo/
adb -s <serial> pull /sdcard/Android/data/nodomain.freeyourgadget.gadgetbridge/files /path/outside/the/repo/
```

Gadgetbridge broadcasts `nodomain.freeyourgadget.gadgetbridge.action.DATABASE_EXPORT_SUCCESS` or
`..._FAIL` after an export if *Broadcast export result* is enabled in the Intent API settings.

## 6. Troubleshooting

- *Export failed, location not set*: the export location in step 4.1 was not chosen with the folder
  picker. Gadgetbridge stores a content URI, a typed path does not work.
- *Intent API ... not allowed* in the Gadgetbridge log: the matching toggle in step 4.2 is off.
- The strap does not connect after entering the key: make sure it is still paired in the Zepp
  account, the Zepp app has no Bluetooth permission, and the key starts with `0x`.
- `adb devices` shows `unauthorized`: confirm the USB debugging prompt on the phone.

## 7. What the exported database contains

Observed in `Gadgetbridge.db` (0.95.1, 182 tables) right after pairing both devices. `DEVICE` maps
`DEVICE_ID` to the gadget (`TYPE_NAME` `GARMIN_FENIX_6X` = id 1, `AMAZFITHELIOSTRAP` = id 2 on this
phone; wristpull resolves this by MAC/type, never by hard-coded id). `USER` holds the profile.

Timestamp units differ per table: `*_ACTIVITY_SAMPLE` tables use **seconds**, almost every other
sample table uses **milliseconds** since the Unix epoch, all UTC.

| Device | Table | Content |
|---|---|---|
| Garmin | `GARMIN_ACTIVITY_SAMPLE` | per minute: steps, heart rate, intensity, distance (cm), active calories; `-1` = not measured |
| Garmin | `GARMIN_BODY_ENERGY_SAMPLE` | body battery (`ENERGY`) |
| Garmin | `GARMIN_STRESS_SAMPLE`, `GARMIN_RESPIRATORY_RATE_SAMPLE`, `GARMIN_HEART_RATE_RESTING_SAMPLE`, `GARMIN_SPO2_SAMPLE` | wellness samples |
| Garmin | `GARMIN_SLEEP_STAGE_SAMPLE`, `GARMIN_SLEEP_STATS_SAMPLE`, `GARMIN_HRV_*`, `GARMIN_INTENSITY_MINUTES_SAMPLE` | sleep, HRV, intensity minutes (empty until the watch delivers them) |
| Garmin | raw FIT files on the file system (section 2) | wristpull prefers these over the tables: same parser as USB |
| Helio Strap | `HUAMI_EXTENDED_ACTIVITY_SAMPLE` | per minute: `RAW_INTENSITY`, `STEPS`, `RAW_KIND`, `HEART_RATE` (`255` = not measured), `SLEEP`/`DEEP_SLEEP`/`REM_SLEEP` flags |
| Helio Strap | `GENERIC_TEMPERATURE_SAMPLE` | skin temperature in °C (`TEMPERATURE_TYPE` 2, `TEMPERATURE_LOCATION` 9) |
| Helio Strap | `HUAMI_PAI_SAMPLE` | PAI score per day (`UTC_OFFSET` in ms) |
| Helio Strap | `HUAMI_STRESS_SAMPLE`, `HUAMI_SPO2_SAMPLE`, `HUAMI_HEART_RATE_RESTING_SAMPLE`, `HUAMI_HEART_RATE_MAX_SAMPLE`, `HUAMI_HEART_RATE_MANUAL_SAMPLE` | wellness samples (fill after the first full day) |
| Helio Strap | `HUAMI_SLEEP_SESSION_SAMPLE` (blob), `HUAMI_SLEEP_RESPIRATORY_RATE_SAMPLE`, `GENERIC_SLEEP_STAGE_SAMPLE`, `GENERIC_SLEEP_SCORE_SAMPLE`, `GENERIC_HRV_VALUE_SAMPLE` | sleep and HRV candidates, to be confirmed with real data |
| both | `BASE_ACTIVITY_SUMMARY` | workouts: start/end, `ACTIVITY_KIND`, `SUMMARY_DATA` (JSON), `GPX_TRACK`, `RAW_DETAILS_PATH` |
| both | `BATTERY_LEVEL`, `DEVICE_ATTRIBUTES` | device battery and firmware |

Cross-check done on 2026-10-31: `GARMIN_BODY_ENERGY_SAMPLE` holds exactly the values the FIT parser
reads from `stress_level` field 3 in the matching `MONITOR_*.fit` files. The field mapping
for body battery is therefore confirmed against Gadgetbridge's own import.
